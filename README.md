# Minecraft Java AOT for iOS — Proof of Concept

**Goal:** Compile Minecraft Java Edition as a GraalVM Native Image for iOS, running on TrollStore without JIT.

## Status

🟢 **Server native image: WORKING** (152MB, boots in 40s)
🟡 **Client native image: boots OK** (179MB, loads LWJGL, fails at RenderSystem on headless terminal — expected)
🔴 **iOS arm64 build: requires arm64 machine** (GitHub Actions workflow included)

## Key Findings

- GraalVM CE does NOT support `--target=ios-arm64` (Oracle confirmed)
- Cross-compile from x86_64 to arm64 fails because native-image must execute target-architecture binaries during build
- Solution: Use GitHub Actions `macos-latest` (Apple Silicon) for arm64 builds
- Log4j lambda classes cause non-fatal `LinkageError: duplicate class definition` at runtime
- LWJGL loads successfully with `DYLD_LIBRARY_PATH` pointing to extracted natives

## Quick Start

```bash
# 1. Setup toolchain
bash scripts/setup_toolchain.sh
source aot-env.sh

# 2. Fetch Minecraft 1.20.1
bash scripts/fetch_minecraft.sh 1.20.1

# 3. Capture reflection configs with agent
bash scripts/capture_agent.sh 1.20.1 90

# 4. Build server native image (desktop test)
bash scripts/build_native_desktop.sh server 1.20.1

# 5. Build client native image (desktop test)
bash scripts/build_native_desktop.sh client 1.20.1
```

## GitHub Actions (arm64 build)

Push to this repo and trigger the workflow:

```bash
# Manual trigger via GitHub UI or:
gh workflow run build-arm64.yml -f mode=server -f mc_version=1.20.1
```

Build artifacts are uploaded for 7 days.

## Launcher Integration (Witch Launcher)

The Witch Launcher (Angel-Aura-Amethyst-iOS) has been modified to support AOT mode:

- `LauncherPreferences.h/m`: JIT/AOT toggle keys
- `PLPreferences.m`: default `execution_mode = "jit"`
- `PLProfiles.m`: execution mode fallback mapping
- `JavaLauncher.m`: AOT path — reads executionMode, resolves native binary at `$POJAV_HOME/instances/<instance>/<version>/native/<versionId>-native`, calls `execv()`
- `ProfileSettingsViewController.m`: picker in profile Java section
- `SettingsViewController.m`: picker in global Game section

## Technical Notes

### Log4j Lambda Issue
The `WatchManager$$LambdaX00cYkMpJz5OQNG2GVGhAF` class causes a non-fatal `LinkageError` because it's both predefined (in native image) and dynamically generated by `InnerClassLambdaMetafactory`. The server/client still works after this error.

### LWJGL Library Loading
In GraalVM native images, `-D` command-line flags are NOT supported. Library paths must be embedded at build time via `-Dorg.lwjgl.librarypath` in the `native-image` command, or set via `DYLD_LIBRARY_PATH` at runtime.

### Cross-Compilation Limitation
GraalVM native-image generates C code for platform-specific queries, compiles it, and executes the resulting binary to gather data. This means:
- Cannot cross-compile from x86_64 to arm64 (binary won't run on wrong arch)
- Must build on target architecture (arm64 Mac for iOS)
- GitHub Actions `macos-latest` provides Apple Silicon runners
